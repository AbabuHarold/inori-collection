# 変更履歴

## v1.1.1（2026-10-28）

公開方法の変更だけです。画面・操作・作品データ・保存形式・バックアップ形式は v1.1.0 と同じです。

### GitHub Pages 対応

- **GitHub Pages（`https://<ユーザー名>.github.io/<リポジトリ名>/`）で公開できるようにしました。**
  - これまでは、ドメイン直下（`/`）で公開することを前提にしていました。
  - そのため GitHub Pages のようにフォルダー（`/inori-collection/`）の下で公開すると、アイコン・Service Worker・マニフェストの場所がずれて動きませんでした。
- 公開先のパスを、ビルド時の環境変数 `BASE_PATH` で指定できるようにしました（未指定なら従来どおり `/`）。
  - マニフェストの開始URL・範囲（scope）・ID・アイコン、画面上部のアイコン、オフライン時の画面の読み込み先が、公開先のパスに合わせて設定されます。
- **公開用ワークフロー `.github/workflows/deploy.yml` を追加しました。**
  - GitHub に置くと、テスト → ビルド → GitHub Pages への公開を自動で行います。
  - テストが失敗したときや、ビルド結果が公開先のパスに合っていないとき（真っ白な画面になる状態）は公開しません。
  - アプリのファイルがリポジトリ直下・`inori-collection` フォルダーのどちらにあっても動きます。
  - ブラウザからのアップロードでファイルが足りない場合は、足りないファイル名を表示して止まります。

### テスト

- GitHub Pages 形式の E2E テスト（`npm run test:e2e:pages`、13 項目）を追加しました。
- 既存の E2E テスト（46 項目）・ユニットテスト（91 件）も v1.1.1 で再実行し、すべて成功しています。
- ドメイン直下で公開する場合（Vercel）のビルド結果は v1.1.0 と同じです（アイコンの指定を相対パスにした以外）。

### ジャケット画像

- 1形態に画像URLの候補を複数持てるようにしました。順番は「キングレコード → 水瀬いのり公式サイト」です。片方の配信元で取得できなくなっても、もう片方で表示を続けます。
- ライブBlu-ray などの縦長・横長のジャケットが切れないよう、全体が収まる表示に変えました（以前は正方形に切り抜き）。
- **端末内キャッシュに保存するのは、「画像として表示できる」と確認したものだけにしました。**
  - 実サーバーでの検証で、公式サイトの 404 ページも「中身の見えない正常な応答」としてキャッシュに保存できてしまうことが分かったためです。
  - Service Worker 自身はジャケット画像を保存しない設定にしました。
- 表示に失敗した画像のキャッシュは削除し、次回オンライン時に取り直すようにしました。

### オフライン準備状況の表示

- 準備状況を3段階に分けました。
  - 「オフラインOK」：すべて保存済み
  - 「画像なし◯件」：取得できる画像はすべて保存済み。取得できなかった形態はCDアイコンで表示
  - 「準備中 / 未準備」
- 画像がすべて取得できない場合（配信元の障害など）は、「オフラインOK」と表示しないようにしました。
- 取得できなかった画像は、設定画面に作品名を表示します。
- 取得できなかった画像は記録しておき、次のときに再試行します。
  - オンライン時に 24 時間ごと（自動）
  - 「取得できなかった画像を再試行」ボタンを押したとき
- オフラインで再起動しても、準備状況の表示が正しく維持されます。

### 不具合修正

- 「更新する」ボタンで画面が切り替わらない不具合を修正しました。
  - 発生条件：初めて開いたその画面のまま、新しいバージョンが届いたとき。
  - 新しいバージョン自体は裏で有効になっていて、開き直すと切り替わっていました。データへの影響はありません。
