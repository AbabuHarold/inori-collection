## A. 実画像の検証（実際の配信サーバー）

E2E とは別に、ユーザーのPCのブラウザから実際の配信サーバーに対して確認しました。アプリと同じく**別サイトのページから**（`https://king-cr.jp` 上で）読み込んでいます。

| 確認項目 | キングレコード画像（34形態分） | 水瀬いのり公式サイト画像（36形態分） |
| --- | --- | --- |
| URLが現在有効か | 34 / 34 有効（200・image/jpeg、709〜2000px） | **2 / 36 のみ有効**（Summer Challenger・10th ANNIVERSARY BD）。他は 404（公式サイト改修中） |
| 別サイトから表示できるか（`<img>`） | 34 / 34 表示可 | 2 / 36 |
| オフラインキャッシュへ保存できるか | 34 / 34 保存可（CORS非対応のため opaque 応答として保存） | ※404 の応答も opaque として保存「できてしまう」ことを確認 → 対策済み（下記） |
| 保存したものを読み出せるか | 34 / 34 読み出し可 | — |

形態ごとの結論：**34 / 36 形態は実際のジャケットを表示可能**。
KICS-93477・KICS-93785（追加した初回限定盤2形態）は、現在どの配信元からも画像を取得できないため CDアイコン表示になります。

この検証で見つかった問題と対策：

- 公式サイトの 404 ページも、ブラウザのキャッシュには「中身の見えない正常な応答」として保存できてしまう。
  - Service Worker 自身はジャケット画像をキャッシュに書き込まない設定に変更。
  - キャッシュへの保存は、アプリ側が「画像として表示できる」ことを確認したものだけに限定。
  - 表示に失敗した画像はキャッシュから消すようにした。

「キャッシュ済み画像をネット接続なしで表示できるか」は、実ブラウザでネットワークを切る操作ができないため、下記 E2E（ダミー画像）で確認しています。

保守用に `npm run check:images` で、いつでも実サーバーの状態を確認できます（あなたのPCで実行）。

## D. 未検証項目（実機での確認が必要）

| 項目 | 理由・確認方法 |
