## A. 実画像の検証（実際の配信サーバー）

E2E とは別に、ユーザーのPCのブラウザから実際の配信サーバーに対して確認しました。アプリと同じく**別サイトのページから**（`https://example.com` 上で）`<img>` で読み込んでいます。

| 確認項目 | キングレコード画像（37形態分） | 水瀬いのり公式サイト画像（39形態分） |
| --- | --- | --- |
| 別サイトから表示できるか | **37 / 37** 表示可（709〜2000px） | **39 / 39** 表示可（750px 前後。新作のみ 2560px） |

- 公式サイトの画像は、リニューアル後の `https://inoriminase.com/wp/wp-content/uploads/<年>/<月>/` で全件表示できました（v1.1.x の旧URLは 404 のため更新）。
- 前回「画像なし」だった KICS-93477・KICS-93785（初回限定盤）も表示できるようになりました。
- 新規3形態（KICM-2183・KIXM-379・KIXM-627）は、キングレコードと公式サイトの画像を並べて同じジャケットであることを目視で確認しました。
- 形態ごとの縦横比（シングル・通常盤は正方形、ライブBD・MUSIC CLIP BOX は縦長、初回限定盤の一部は横長）も両配信元で一致しています。

保守用に `npm run check:images` で、いつでも実サーバーの状態を確認できます（あなたのPCで実行）。

| 実機でのオフライン表示（配信元の実画像） | オフライン表示はダミー画像の E2E でのみ確認。実画像の表示はPCのブラウザで確認済み |

| 実機のストレージ容量・保存領域の保護（persist） | ブラウザ・端末設定に依存 |
| GitHub Actions 上でのワークフロー実行（特に `INORI_EDITION=public`） | 手順はこちらで再現済み。実際の GitHub 上での実行を確認する |
| GitHub Pages（`https://<ユーザー名>.github.io/inori-collection/`）からのジャケット画像の表示（個人用版） | 別サイト（example.com）のページからの表示は確認済み |
