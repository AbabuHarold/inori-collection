# Inori Collection

水瀬いのりさん本人名義の **CD（シングル・アルバム）・ライブBlu-ray・MUSIC CLIP BOX** の所持状況を管理する PWA（ホーム画面に追加できる Web アプリ）です。

- iPhone / Android のブラウザで動作し、ホーム画面に追加するとアプリとして起動できます
- ログイン・サーバー・データベースは不要。所持データはスマートフォンのブラウザ内に自動保存されます
- 機種変更は ZIP ファイル 1 つで引き継げます（iPhone ⇔ Android 間も可）
- 初回準備後はオフラインでも使えます
- **2つの版**をビルドできます（[2つの版](#2つの版個人用版公開版)）
  - **個人用版**（既定）：ジャケット画像を公式の配信元から読み込んで表示
  - **公開版**：画像を配信元から一切取得せず、使う人が自分で撮影した写真などを後から設定

> 非公式のファンメイドアプリです。作品情報の出典は水瀬いのり公式サイト（ディスコグラフィー）とキングレコード公式サイトです。個人用版のジャケット画像は両公式サイトの配信画像、公開版は使う人が自分で設定した画像です。

## できること

| 機能 | 内容 |
| --- | --- |
| 一覧表示 | 全 39 形態（32 作品）をジャケット付きで表示。グリッド（スマホは 2 列）とリストを切り替え |
| 作品の詳細 | ジャケットをタップすると、品番・発売日・所持枚数・公式ページへのリンクを表示 |
| ジャケット画像の設定 | 形態ごとに自分で用意した画像（撮影した写真など）を設定・変更・削除。縮小して端末内にだけ保存（位置情報などは保存しない） |
| 所持枚数 | 形態ごとに「未開封」「開封済」を一覧から直接 ＋ / − で変更。0 未満にはならない |
| 元に戻す | 変更直後に画面下へ「元に戻す」を表示（数秒以内なら連続して戻せる） |
| 自動保存 | 変更は即座に端末内へ保存。保存に失敗したら画面上部に通知 |
| 所持バッジ | 未所持 → 「未所持」、所持 → 「所持 3枚」。ジャケットは常にカラー |
| 絞り込み | カテゴリー（シングル / アルバム / ライブBlu-ray / MUSIC CLIP BOX）/ 所持状況 / 開封状態 / 作品名検索（すべて組み合わせ可） |
| 並び替え | 発売日が古い順（初期値）/ 新しい順 / 作品名順 / カテゴリー順 |
| 表示設定の保存 | 表示形式・絞り込み・検索語・並び順を保存し、次回起動時に復元 |
| 集計 | 所持作品数 / 総所持枚数 / 未開封枚数 / 開封済枚数 / コンプリート率 |
| バックアップ | ZIP で保存・復元（自分で設定した画像も含む。内容を検証してから、確認画面を経て反映） |
| オフライン | アプリ本体とジャケット画像（個人用版は配信元の画像、公開版は自分で設定した画像）を端末内に保存し、ネット接続なしで起動・操作 |

## 2つの版（個人用版・公開版）

同じソースコードから、ビルド時の指定で2つの版を作れます。所持データ・バックアップの形式は共通で、どちらの版で作ったバックアップもう一方の版で復元できます。

| | 個人用版（personal・既定） | 公開版（public） |
| --- | --- | --- |
| ジャケット画像 | キングレコード・水瀬いのり公式サイトの配信画像を読み込み、端末内にキャッシュして表示 | **配信元から一切取得しない**。ビルドにも画像URLを含めない |
| 自分で設定した画像 | 設定できる（公式の画像より優先して表示） | 設定できる（これが唯一の画像） |
| ビルド | `npm run build` | `npm run build:public`（または環境変数 `INORI_EDITION=public`） |
| 向いている使い方 | 自分だけで使う | URL を他の人に教えて使ってもらう |

公開版は、公式サイトの画像を他の人の端末に配ることになる「画像の読み込み」をしません。画像はそれぞれの人が手持ちのCD・Blu-rayを撮影するなどして、自分の端末の中で設定します（どこにも送信されません）。

公開版のビルドに画像URLが含まれていないことは、`npm run test:e2e:public` と GitHub Actions の公開ワークフロー（公開版のとき）で毎回確認しています。

## 使い方

1. 公開した URL をスマートフォンのブラウザで開きます。
2. ホーム画面に追加します。
   - **iPhone（Safari）**：共有ボタン → 「ホーム画面に追加」
   - **Android（Chrome）**：右上メニュー → 「ホーム画面に追加」または「アプリをインストール」
3. ホーム画面のアイコン（水色の背景に白い CD）から起動します。
4. 各作品の「未開封」「開封済」の ＋ / − を押すだけで管理できます。
5. ジャケット部分をタップすると作品の詳細が開きます。「画像を選ぶ」で、カメラロールの写真などをその形態のジャケット画像に設定できます（公開版で画像を表示するにはこの方法で設定します）。

右上の歯車ボタンから「設定」（バックアップ・復元・オフライン準備状況）を開けます。
ヘッダーの小さな表示はオフライン準備の状況です（`オフラインOK` ＝すべて準備完了、`画像なし◯件` ＝準備完了だが一部の形態は配信元から画像を取得できずCDアイコン表示、`準備中` / `オフライン未準備` ＝未完了）。公開版は配信元の画像を使わないため、アプリ本体を保存できれば `オフラインOK` になります。

## 機種変更（バックアップと復元）

**古いスマートフォン**

1. Inori Collection → 設定 → **バックアップを作成**
2. `inori-collection-backup-YYYY-MM-DD.zip` が保存されます
   - iPhone では「共有メニューから保存」ボタンで「ファイル」アプリや AirDrop にも保存できます
3. ZIP を新しいスマートフォンへ移します（クラウドストレージ、メール添付、PC 経由など）

**新しいスマートフォン**

1. Inori Collection を開く（ホーム画面に追加しておく）
2. 設定 → **バックアップから復元** → ZIP を選ぶ
3. ファイルの内容が検証され、確認画面（作成日時・形態数・枚数）が表示されます
4. 「復元する」を押すと所持枚数・表示設定・自分で設定した画像が復元されます（直後なら「元に戻す」で取り消し可）

安全のための仕様：

- ZIP の中身はテキスト（UTF-8 の JSON）1 ファイルと、自分で設定した画像（`jackets/<品番>.jpg`）だけなので、iPhone / Android どちらで作っても同じ形式です
- 画像は、復元するとバックアップの内容に**置き換わります**（確認画面に枚数を表示）。ただし v1.1.1 以前に作ったバックアップ（画像の情報がない）を復元したときは、今の端末の画像をそのまま残します
- 検証がすべて通るまで現在のデータは一切変更しません。復元中の保存に失敗した場合も既存データを維持します
- 不正な ZIP（ZIP でない・中身が違う・巨大すぎる・ファイル数が多すぎる・枚数がマイナスや小数・画像が壊れている／画像でないなど）は拒否します
- 現在の作品データにない ID が含まれていても破棄せずに保持します（将来の作品データ更新で復活できるように）
- バックアップにはデータ形式のバージョンを記録しており、古いバックアップも読み込めるようにしています（v1.2.0 で作ったバックアップは v1.1.1 以前のアプリでは読めません。アプリを更新してから復元してください）

> バックアップ ZIP はスマートフォン以外の場所（クラウドや PC）にも保管しておくのがおすすめです。
> ブラウザのデータ削除やアプリの削除をすると、端末内の所持データも消えます。

## オフライン利用について

- 初回にオンラインで開くと、アプリ本体（HTML / JS / CSS / アイコン）と、各形態のジャケット画像（個人用版のみ）が端末内に保存されます。
- 自分で設定した画像は、設定した時点で端末内（IndexedDB）に保存されるので、最初からオフラインで表示できます。
- 準備状況はヘッダーと設定画面に表示されます。**「オフラインOK」または「画像なし◯件」になるまではオフライン対応が完了していません。**
- 配信元から取得できなかった画像は、設定画面に作品名を表示します。オンライン時は 24 時間ごとに自動で、または設定画面の「取得できなかった画像を再試行」でいつでも取り直せます。
- ジャケット画像は約数 MB〜十数 MB です。可能なら Wi-Fi 環境で最初に開いてください。
- 途中で失敗した画像は、オンライン時に設定画面の「ジャケット画像をオフライン用に保存」で再取得できます。
- アプリを更新しても、所持データ（localStorage）と画像キャッシュ（Cache Storage）は消えません。更新は画面上部の「更新する」を押したときだけ適用されます。

### ジャケット画像の扱い

公式サイトのジャケット画像には再配布を許可する利用条件が見当たらなかった（各ページは All Rights Reserved 表記、公式サイトは画像保存を抑止する仕組みあり）ため、**画像ファイルはこのアプリ（リポジトリ・公開先）に同梱していません**。
アプリは公式の配信 URL を参照し、閲覧した端末の中にだけキャッシュとして保存して表示します。

- 1つの形態に画像URLの候補を複数持ち、順番に試します：①キングレコード公式 → ②水瀬いのり公式サイト。配信元の仕様変更などで①が取得できなくなっても②で表示を続けます。
- 画像URLの一覧は `src/data/jackets.ts` にあります（公開版のビルドでは空の `src/data/jackets.public.ts` に差し替わります）。
- どの候補も取得できない形態は CDアイコンを表示します。2026-11-23 時点では、全39形態が表示できることを確認済みです（公式サイトのリニューアルで画像の場所が変わったため v1.2.0 で更新。v1.1.x で表示できなかった初回限定盤2形態も表示されるようになりました）。
- 自分で画像を設定した形態は、その画像を優先して表示します。
- 端末内に保存するのは「画像として表示できる」ことを確認したものだけです（404 のページなどを誤って保存しないため）。
- 画像URLが今も有効かは `npm run check:images` でいつでも確認できます。

## 開発環境の準備（Windows）

必要なもの：

- [Node.js](https://nodejs.org/) **22.12 以上**（LTS 版のインストーラーで OK）
- [Git](https://git-scm.com/)（GitHub 経由でデプロイする場合）

PowerShell で：

```powershell
cd inori-collection
npm install          # 依存パッケージのインストール
npm run dev          # 開発サーバー → http://localhost:5173 を開く
```

主なコマンド：

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 開発サーバー（Service Worker は本番ビルドでのみ有効） |
| `npm run build` | 型チェック + 本番ビルド（個人用版。`dist/` に出力） |
| `npm run build:public` | 型チェック + 本番ビルド（公開版。`dist/` に出力） |
| `npm run preview` | 本番ビルドをローカルで確認（PWA・オフラインの確認はこちら） |
| `npm test` | ユニットテスト（128 件） |
| `npm run test:e2e` | 実ブラウザでの E2E テスト（個人用版。初回は `npx playwright install chromium` が必要） |
| `npm run test:e2e:public` | 公開版の E2E テスト（画像を取得しないこと・自分で設定した画像・バックアップ） |
| `npm run test:e2e:pages` | GitHub Pages 形式（`/inori-collection/` 配下）で公開したときの E2E テスト |
| `npm run check:images` | ジャケット画像URLが実際の配信元で有効か確認（インターネット接続が必要） |
| `npm run icons` | アプリアイコン PNG の再生成 |

同じ Wi-Fi のスマートフォンで試す場合は `npm run preview -- --host` を実行し、表示された `http://192.168.x.x:4173` を開きます（ただし http のため Service Worker・オフライン機能は動きません。PWA の確認は GitHub Pages や Vercel に公開して https で行ってください）。

## GitHub Pages への公開手順

GitHub の無料機能「GitHub Pages」で `https://<ユーザー名>.github.io/<リポジトリ名>/` に公開できます。
テスト → ビルド → 公開は、同梱の **`.github/workflows/deploy.yml`** が GitHub 上で自動的に行います（PC に Node.js がなくても公開できます）。

> **注意**：このアプリはビルド（変換）してから公開する必要があります。リポジトリのファイルをそのまま公開する設定（Settings → Pages の「Deploy from a branch」）では動きません（404 や真っ白な画面になります）。必ず下の手順 3 の「GitHub Actions」を選んでください。

### 手順

1. GitHub でリポジトリを作成し、このフォルダーの中身をアップロード（または push）します。
   - アプリのファイル（`package.json` など）は、**リポジトリの直下**、または **`inori-collection` フォルダーの中**のどちらに置いても動きます。
   - `src`・`tests`・`public` などを含む**一式すべて**が必要です（足りない場合、ワークフローの「Check the app files」で足りないファイル名を表示して止まります）。
2. **`.github/workflows/deploy.yml` をリポジトリの直下に置きます**（`inori-collection` フォルダーの中に置いた場合は動きません）。
   - ブラウザからアップロードする場合、`.` で始まるフォルダーはドラッグ＆ドロップで送られないことがあります。そのときは GitHub の **Add file → Create new file** でファイル名に `.github/workflows/deploy.yml` と入力し、ファイルの内容を貼り付けて保存してください。
3. リポジトリの **Settings → Pages → Build and deployment → Source** を **「GitHub Actions」** にします（最初に1回だけ）。
4. **Actions** タブで「Deploy to GitHub Pages」が実行され、緑のチェックになれば公開完了です。
   - すでにファイルを置いた後で手順 3 を行った場合は、Actions タブ →「Deploy to GitHub Pages」→ **Run workflow** で実行します。
   - テストが1件でも失敗した場合や、ビルド結果が公開先のパスに合っていない場合（アプリのファイルが古い・置き場所が違うなど）は公開しません（それまで公開していたアプリはそのまま残ります）。
5. `https://<ユーザー名>.github.io/<リポジトリ名>/` をスマートフォンで開き、ホーム画面に追加します（[使い方](#使い方)）。

以後は main ブランチを更新する（ファイルをアップロードし直す・push する）たびに、自動で再公開されます。

### 公開版を GitHub Pages で公開する

リポジトリの **Settings → Secrets and variables → Actions → Variables** タブ → **New repository variable** で、次の変数を追加します。

| Name | Value |
| --- | --- |
| `INORI_EDITION` | `public` |

追加したあと、Actions タブ →「Deploy to GitHub Pages」→ **Run workflow** で公開し直すと、公開版になります（ワークフローがビルドに画像URLが含まれていないことを確認してから公開します）。変数を削除する（または `personal` にする）と個人用版に戻ります。

> 同じ URL で版を切り替えても、各端末の所持データ・自分で設定した画像はそのまま残ります。
>
> 個人用版と公開版は、別々のリポジトリ（個人用版 `inori-collection`・公開版 `inori-collection-public`）で管理しています。どちらも同じユーザーの GitHub Pages（`https://<ユーザー名>.github.io/…/`）に公開すると、ドメインが同じなので、**同じスマートフォンで両方を開いたときは所持データ・表示設定・自分で設定した画像が共通**になります（データの形式は同じなので壊れることはありません）。別々に管理したい場合は、片方を Vercel など別のドメインに公開してください。スマートフォンでアプリを開くと「新しいバージョンがあります」と表示されるので「更新する」を押してください。

公開先のパス（`/<リポジトリ名>/`）はワークフローが自動で設定します（環境変数 `BASE_PATH`）。リポジトリ名を変えると URL も変わり、**別のアプリ扱い（所持データは引き継がれない）**になるので、変える場合は先にバックアップを作成してください。

> GitHub Pages で公開したサイトは、リポジトリが Private でも URL を知っている人は誰でも開けます（無料プランでは Public リポジトリのみ GitHub Pages を利用可）。所持データは各自の端末内にしか保存されないため、他の人にあなたのデータが見えることはありません。

## Vercel へのデプロイ手順

Vercel の無料プラン（Hobby）で公開できます。設定は `vercel.json` に入っているので、基本的に入力するものはありません。

### 方法 A：GitHub 経由（おすすめ・更新が楽）

1. GitHub で新しいリポジトリを作成（**Private 推奨**）
2. このフォルダをプッシュ
   ```powershell
   cd inori-collection
   git init            # 同梱の .git がある場合は不要
   git add -A
   git commit -m "Inori Collection"
   git branch -M main
   git remote add origin https://github.com/<あなたのユーザー名>/inori-collection.git
   git push -u origin main
   ```
3. [vercel.com](https://vercel.com/) に GitHub アカウントでログイン → **Add New… → Project**
4. 作成したリポジトリを **Import**
5. Framework Preset が **Vite**、Build Command が `npm run build`、Output Directory が `dist` になっていることを確認して **Deploy**
6. 発行された `https://〜.vercel.app` をスマートフォンで開き、ホーム画面に追加

以後は GitHub に push するたびに自動で再デプロイされます。

公開版にする場合は、Vercel のプロジェクトの **Settings → Environment Variables** に `INORI_EDITION` = `public` を追加して、再デプロイします。

### 方法 B：Vercel CLI

```powershell
npm install -g vercel
cd inori-collection
vercel          # 初回は質問に答える（設定は既定のままで OK）
vercel --prod   # 本番公開
```

### デプロイ後の確認

- スマートフォンで開き、ヘッダーが「オフラインOK」になるまで待つ（2026-11-23 時点では全形態の画像を取得できるため「オフラインOK」が正常。公開版はアプリ本体の保存だけで「オフラインOK」になります）
- 機内モードにしてホーム画面から起動し、一覧・ジャケット・＋ − が動くことを確認
- 一度「バックアップを作成」して ZIP が保存できることを確認

> URL を知っている人は誰でもアプリを開けますが、所持データは各自の端末内にしか保存されないため、他の人にあなたのデータが見えることはありません。

## 新作が出たときの更新

アプリ内で作品を手動登録する機能はありません。作品マスター（`src/data/releases.ts`）を更新して再デプロイします。
手順と Claude への依頼文テンプレートは **[docs/UPDATING.md](docs/UPDATING.md)** にまとめています。

要点：

- 既存作品の `id` は**絶対に変更しない**（所持データとバックアップのキー）
- 新作は配列に追加するだけ。所持枚数は自動的に 0 から始まります
- ジャケット画像のURLは `src/data/jackets.ts` に追加します（公開版には含まれません）
- 既存の所持データ・バックアップはそのまま使えます

## 設計メモ（データの守り方）

```
src/
  data/
    releases.ts        作品マスター（静的データ。新作はここに追加）
    jackets.ts         ジャケット画像の配信元URL（個人用版）
    jackets.public.ts  同・公開版（空。ビルド時に jackets.ts と差し替え）
    types.ts           作品データの型
  edition.ts           個人用版 / 公開版の判定
  lib/
    collection.ts      枚数変更・集計・絞り込み・並び替え（純粋関数）
    storage.ts         端末内保存（localStorage）・破損時の退避
    backup.ts          ZIP バックアップの作成・検証・バージョン移行
    offline.ts         配信元のジャケット画像のオフライン保存（個人用版）
    userJackets.ts     自分で設定した画像の保存（IndexedDB）
    imageProcess.ts    選んだ画像の縮小・JPEG 変換
  components/          画面部品（DetailSheet.tsx = 作品の詳細・画像の設定）
  App.tsx              画面全体と状態管理
tests/                 ユニットテスト（Vitest）
e2e/                   E2E テスト（Playwright + Chromium。run.mjs = 個人用版、public.mjs = 公開版、pages.mjs = GitHub Pages 形式）
docs/               データ報告・更新手順・テスト結果
```

- **作品マスターと所持データは分離**しています。所持データは `{ 品番ID: { unopened, opened } }` だけを保存します。
- **ID は代表品番**（例 `KICS-93710`）。品番は変わらないため、作品データを更新しても所持枚数がずれません。
- **保存先**：所持データ `inori-collection/collection`、表示設定 `inori-collection/settings`（localStorage）。Service Worker のキャッシュとは別領域なので、アプリ更新で消えません。
- **画像の準備状況**：取得できなかった画像の記録 `inori-collection/jacket-unavailable`（消えても再試行するだけ）。画像本体は Cache Storage `inori-jackets-v1`（アプリ更新で消えない）。
- **自分で設定した画像**：IndexedDB（データベース `inori-collection`・ストア `user-jackets`）。形態IDごとに、長辺800pxに縮小したJPEG（通常 50〜300KB）を保存。アプリ更新で消えない。別のタブで開いている画面にもすぐ反映。
- **破損対策**：読み込み時に検証し、壊れていた場合は元データを `inori-collection/corrupted/<日時>` に退避してから起動します。退避できない場合は自動保存を止めて上書きを防ぎます。
- **容量超過**：保存に失敗しても画面の状態は保ち、エラーを表示して「再試行」できます。
- **端末の保存領域保護**：起動時に `navigator.storage.persist()` を要求します（ブラウザが許可した場合のみ有効）。

### バックアップ形式（schemaVersion 2）

ZIP 内の `inori-collection-backup.json` と、自分で設定した画像 `jackets/<形態ID>.jpg`：

```json
{
  "format": "inori-collection-backup",
  "schemaVersion": 2,
  "createdAt": "2026-11-23T12:34:56.000Z",
  "app": { "name": "Inori Collection", "masterVersion": "2026-11-23", "version": "1.2.0", "edition": "public" },
  "collection": { "KICM-1641": { "unopened": 1, "opened": 2 } },
  "settings": { "view": "grid", "category": "all", "owned": "all", "open": "all", "query": "", "sort": "dateAsc" },
  "jackets": {
    "KICM-1641": { "file": "jackets/KICM-1641.jpg", "type": "image/jpeg", "bytes": 84213, "updatedAt": "2026-11-23T12:00:00.000Z" }
  },
  "summary": { "forms": 1, "unopened": 1, "opened": 2, "jackets": 1 }
}
```

- `jackets` が `{}` のバックアップを復元すると、自分で設定した画像はなくなります（バックアップの状態に揃える）。
- `jackets` が `null`（画像の保存領域を使えない端末で作成）や、schemaVersion 1（v1.1.1 以前）のバックアップは「画像の情報なし」として扱い、復元しても今の画像を変更しません。

安全上の上限：ZIP 64 MB / エントリ 2,020 個 / 展開後 JSON 1 MB / 所持データ 10,000 件 / 1 形態あたり 999 枚 / 画像 1 枚 2 MB・合計 60 MB・1,000 枚。画像はZIP内のパス・大きさ・中身（先頭のバイト列）を検証します。
形式を変える場合は `src/lib/backup.ts` の `BACKUP_SCHEMA_VERSION` を上げ、`MIGRATIONS` に旧→新の変換を追加し、`tests/fixtures/` の旧形式サンプルが読めることをテストで確認してください。

## 既知の制限・注意事項

- 『未解決で、ロマンスで。』（2027-01-27 発売予定）の情報は発売前のものです。発売後に形態や収録内容が変わった場合は作品データを更新してください。
- v1.2.0 で作成したバックアップは、v1.1.1 以前のアプリでは復元できません（「新しいバージョンのアプリで作成されたバックアップです」と表示されます）。両方の端末を v1.2.0 以降にしてから復元してください。
- 自分で設定した画像は、画面上で切り抜き・回転はできません（画像全体をジャケット枠に収めて表示します）。必要ならスマートフォンの写真アプリで切り抜いてから選んでください。
- v1.0.0 では、初めて開いたその画面のまま更新が届いた場合に「更新する」を押しても画面が切り替わらないことがありました（開き直せば新しいバージョンになり、データは保持されます）。v1.1.0 で修正済みです。
- iPhone・Android の実機での動作確認はしていません（ヘッドレス Chromium での自動テストのみ）。
- iPhone では、ホーム画面に追加せずに Safari で長期間（7 日以上）開かないと、サイトデータが削除される場合があります。**ホーム画面に追加して使い、定期的にバックアップを取ってください。**
